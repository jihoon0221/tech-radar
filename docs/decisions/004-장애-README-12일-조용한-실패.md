# 004. 장애 회고: README 수집이 12일 동안 조용히 실패했다

- 기간: 2026-10-28 ~ 2026-11-08 (발견 11-08)
- 증상: 매일 수집 결과가 `[error] ... README 0개`. 검색과 스타 추적은 정상이라 데이터는 계속 쌓였지만, 새 저장소의 README 가 하나도 저장되지 않았다. 같은 기간 DB 백업도 빠졌다.
- 왜 몰랐나: 실패 알림은 텔레그램으로 보내게 만들었지만 봇 토큰을 아직 넣지 않았다. 알림 코드는 "설정이 없으면 조용히 넘어간다"로 되어 있었다.
- 근본 원인
  1. 직접 원인: 추적 중이던 `NVIDIA/flare-local-inference` 의 이름이 바뀌어 GitHub 가 301(영구 이동)로 응답했고, 클라이언트가 리다이렉트를 따라가지 않아 오류로 처리했다. (journalctl: `조회 실패 NVIDIA/flare-local-inference 301`)
  2. 실패 범위: 저장소 하나의 오류가 그날 수집 전체를 끝냈다. 추적 단계에서 끝나 README 단계는 매일 실행조차 되지 않았다(README 0개).
  3. 백업 조건: 백업을 ExecStartPost 에 걸어 수집이 성공한 날에만 돌았다.
  4. 관측: 알림 채널이 없는 상태로 운영을 시작했다.
- 조치
  - 저장소 단위로 실패를 격리하고, 실패가 있으면 상태를 `partial` 로 남기고 목록을 출력·알림한다. 실패한 README 는 저장하지 않아 다음 날 다시 시도한다.
  - 이름이 바뀐 저장소의 301 리다이렉트를 따라가고, DB 의 옛 이름 기록(스타 이력·README)을 새 이름으로 옮긴다.
  - 백업을 ExecStopPost 로 옮겨 성공·실패와 상관없이 돈다.
  - 검색 결과가 기준(10건)보다 적으면 알림(데이터 품질 검사).
  - 장애를 그대로 재현하는 테스트를 추가했다.
- 교훈: "실패하면 알린다"는 알림 채널이 실제로 연결돼 있을 때만 성립한다. 운영을 시작하기 전에 알림부터 연결한다.
