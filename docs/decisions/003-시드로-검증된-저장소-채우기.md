# 003. 최근 뜬 것만으로는 좋은 추천이 안 된다 → 시드로 검증된 저장소를 먼저 채운다

- 날짜: 2026-10-26
- 문제: "FastAPI로 실시간 알림 만들 건데 뭐 써?" 같은 질문의 정답은 대개 이미 검증된 오래된 라이브러리다. 매일 수집기만 있으면 DB에는 최근 몇 주 사이 스타가 오른 저장소만 남아, 챗봇이 유행하는 신생 프로젝트만 추천하게 된다.
- 결정: 관심 토픽 41개(`config/topics.txt`)마다 스타 1,000 이상 + 최근 1년 안에 커밋된 저장소 상위 30개를 `source=seed`로 한 번 채운다. 개발 도구 토픽도 넣어 "범용 셋업 추천"의 재료로 쓴다.
- 규칙: 시드는 매일 스타 추적과 급상승 순위에서 제외하고 월 1회 갱신한다. 트렌딩 저장소가 나중에 시드 조건을 만족하면 시드로 올리고, 시드는 다시 내려가지 않는다.
- 답변 설계: 챗봇은 "검증된 기본 선택(시드) / 최근 뜬 것(트렌딩) / 같이 세팅하면 좋은 도구(dev-tool)"로 나눠 답한다.
- 고려한 대안: awesome 목록 파싱 → 사람이 고른 좋은 신호지만 형식이 제각각이라 2차로 미룸.
